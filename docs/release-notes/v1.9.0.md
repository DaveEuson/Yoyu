## Yoyu v1.9.0

**What happens after the limits run out.** Going over your plan and running on
usage credits used to look exactly like sitting at 100% used — the one moment
the board most needed to say something different.

### Credits

When a billing period tips past your plan limits and starts spending credits,
the board says so: a **Credits** row with the money where the percentage goes,
and a line underneath saying what it is.

It appears only once credits are actually being spent. Having them available is
a fact about your account; spending them is a fact about today, and only the
second earns a row on a small screen.

Three states are told apart, because what you'd do about them differs:

| | |
|---|---|
| **past your plan limits** | running on credits |
| **spend limit reached** | the cap stopped you |
| **credits stopped** | switched off some other way, mid-period |

Money is formatted from the currency the account actually reports, honouring its
decimal places rather than assuming two.

**Phone alerts** get two new ones, and neither is tied to the percentage
threshold: the first time a period starts spending credits, and again if the
spend limit is reached. The useful moment is the first cent, whatever the cap
happens to be.

### The rest of the product now knows about it

Credits were not just a new row. Three things elsewhere still behaved as though
running out of plan allowance meant stopping work:

- **The Timer takeover.** When a window hit zero the board seized the screen
  for a countdown to the reset, on the reasoning that the only useful number
  then is how long until you can work again. With credits available that is
  false — you never stopped working, you started paying — and taking the screen
  for a countdown to something that is not blocking you is worse than leaving
  it alone. It now only takes over when credits cannot absorb the overflow.
- **The Focus projection.** *"Runs dry ~2h early"* in red is a wall. With
  credits waiting it is the point the cost starts: the same number, different
  news. It no longer wears the same red, and says where the overflow goes.
  Focus also states outright when money is already being spent.
- **The tray icon** now follows whichever character your board wears, instead
  of always being the fox. Each carries the feed colour somewhere that belongs
  to it — the candle's flame, the plant's growing tip, the moon's lit limb, the
  kitsune's and cat's ears.

### The boards stop going dark on their own

A rejected token used to be permanent. `expiresAt` would say the login was
fine, so the companion took its fast path and handed back the cached token,
and the API rejected it every cycle — because refresh tokens rotate, and
anything else using the same login can invalidate ours while our own clock
still looks healthy. The boards went quiet and stayed quiet until somebody
noticed and ran `claude /login` by hand.

A 401 now costs one forced refresh and one retry. If that does not help, the
refresh token is spent too and the message says so rather than leaving you to
guess. Only 401 retries — a rate limit must back off, not spend a refresh
token discovering it is still rate limited.

### Smaller things

- **Internal codenames no longer take a meter slot.** The usage endpoint
  returns entries beside the real windows that are not user-facing limits, and
  a board with three slots was spending one on "Nimbus Quill 0%". A known
  window always shows, and an unknown one with a reset time still shows — that
  is what a future model looks like — but an unknown entry with no reset and
  nothing used is dropped.
- **`battery_mv` is reported** on the 2″ board, alongside the percentage. With
  no cell fitted the charger holds the pin near the rail and the curve reads
  that as a full battery; a charged cell on USB sits in the same place, so no
  honest threshold separates them. Rather than guess one and risk calling a
  real battery missing, the reading behind the percentage is now visible.
- `/api/status` also reports `credits`.

### Upgrading

Over the air from `/update`, or re-flash from the setup page. Wi-Fi, login,
settings, character and history all survive.
