## Yoyu v1.10.0

**The companion installs itself properly now, and stopped doing it behind your
back.** This release is all companion and documentation. The firmware is
unchanged apart from its version string.

### The old auto-install was a bad idea twice over

Until now the companion added itself to your login items on its own, the first
time it managed to push usage to a board. Nobody asked it to. Deciding that a
program should start with somebody's computer is theirs to decide, and it was
making that call quietly.

It was also recording the wrong path. The login item pointed at wherever the
binary happened to be sitting, which for something you download and
double-click is your Downloads folder. Empty Downloads and start-up breaks,
with nothing on screen to tell you why.

### What replaced it

Installing is now something you ask for, from the tray menu (**Install on this
computer**) or the command line:

```
YoyuCompanion --install
```

It copies the app to a per-user location, so no administrator prompt:

| | |
|---|---|
| Windows | `%LOCALAPPDATA%\Programs\Yoyu` |
| macOS | `~/Library/Application Support/Yoyu` |
| Linux | `~/.local/share/yoyu` |

Then it makes a real shortcut or launcher entry, and offers to start it at
login. Say no and it still installs, just without the login item. Run
`--install` again over an existing copy and it upgrades in place; Windows
cannot overwrite a running executable, so the old one is set aside and swept
away the next time the app starts. `--uninstall` removes all of it and leaves
your configuration alone.

If you never install it, the companion still runs from wherever you put it. It
prints a one-line tip about `--install` instead of acting on its own.

### Antivirus warnings, and something to check them against

While testing the installer, Windows Defender quarantined a build and called it
potentially unwanted software. That is a false positive that unsigned
[PyInstaller](https://pyinstaller.org) programs attract, because the launcher
unpacks itself to a temporary folder when it starts, which is also what some
malware does.

The documentation only warned about the milder SmartScreen prompt, so
[the troubleshooting guide](../TROUBLESHOOTING.md#windows-or-macos-blocks-the-companion-download)
now covers all three cases, including macOS Gatekeeper.

Telling somebody to add an antivirus exclusion is only reasonable if they can
first confirm the file is the one the build produced, and releases were
publishing no checksums at all. **From this release on, every release includes
a `SHA256SUMS.txt`** covering every file it publishes, and the build fails if
that file is missing. v1.9.1 and earlier have none, and there is no way to add
one after the fact.

Anyone who would rather not touch their antivirus settings can run the
companion from source instead. It needs Python, `pystray`, `pillow` and
`certifi`, and it is the same code.

### Also

The release notes and documentation were rewritten to read like a person wrote
them.

### Upgrading

**Boards can skip this one.** Nothing in the firmware changed except the
version it reports, so a board on v1.9.1 behaves identically to one on
v1.10.0. Update it if you would rather the numbers match.

For the companion, download it again from the setup page and run `--install`,
or use **Install on this computer** in the tray menu. An existing install
upgrades in place.
