## Yoyu v1.7.1

**Touch driver corrections for the AMOLED board.** Touch still does not work on
it — but two things in the driver were genuinely wrong, and both of them made a
broken part look like a working one.

### The work mode was never actually being set

A CST92xx will not act on a work-mode write that has not been preceded by an
unlock: `0xD11E`, written twice, confirmed by the chip echoing `0x1E` back at
`0x0002`. Yoyu wrote `0xD109` cold.

The trap is that the mode read-back returns whatever you asked for **either
way**. So the board printed `work mode -> 0x09 (wanted 0x09)` at boot, which
read as success, while the controller carried on not scanning the panel. The
unlock is now performed and confirmed, and the board says so when it fails.

### The chip was never actually identified

Chip type is the *high* pair of the four bytes at `0xD204`; the project id is
the low pair. Yoyu read the low pair and printed it as the id. What looked like
a verified CST9220 was the project id, `0x542F`.

### Three checks that were never being made

The vendor's own driver refuses the part outright in three cases, none of which
Yoyu tested for:

- **No firmware** — the version register reads `0xA5A5A5A5`. Such a chip still
  answers on I²C, still reports the resolution held in its ROM and still accepts
  a mode write. It simply never scans.
- **A garbled info block** — the check code's high half is not `CACA`.
- **The wrong part entirely.**

All three previously presented identically: *initialises fine, never reports a
press.* The board now names which one it hit.

### What this tells us about the AMOLED

On the board here, all three checks now pass — check code `CACA4E20`, chip type
`0x9220`, firmware `01000006`, resolution 480×480, and the mode unlock confirms.
Waveshare's own `pin_config.h` matches every pin Yoyu uses (SDA 15, SCL 14,
INT 11, RST 40).

So the controller is the right part, it is programmed, it is addressed
correctly, and it is in normal reporting mode — and it still reports no press.
That rules out the missing-firmware theory this work started from, and leaves
the panel-to-controller connection as what remains.

**The AMOLED board is still a display, not a control.** Auto-rotate cycles the
screens and everything else is configured from a browser.

### Upgrading

Over the air from `/update`, or re-flash from the setup page. Wi-Fi, login,
settings and history all survive.
