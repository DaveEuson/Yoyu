## Yoyu v1.7.1

**Touch driver corrections for the AMOLED board.** Touch still does not work on
it. But two things in the driver were wrong, and both made a broken part look
like a working one.

### The work mode was never being set

A CST92xx ignores a work-mode write unless you unlock it first: `0xD11E`,
written twice, confirmed by the chip echoing `0x1E` back at `0x0002`. Yoyu
wrote `0xD109` cold.

The trap is that the mode read-back returns whatever you asked for either way.
So the board printed `work mode -> 0x09 (wanted 0x09)` at boot, which looks like
success, while the controller carried on not scanning the panel. The unlock now
happens, gets confirmed, and the board complains when it fails.

### The chip was never being identified

Chip type is the *high* pair of the four bytes at `0xD204`. The project id is
the low pair. Yoyu read the low pair and printed it as the id, so what looked
like a verified CST9220 was the project id, `0x542F`.

### Three checks that were never made

The vendor's own driver refuses the part in three cases. Yoyu tested for none of
them:

- **No firmware.** The version register reads `0xA5A5A5A5`. Such a chip still
  answers on I²C, still reports the resolution held in its ROM, still accepts a
  mode write. It never scans.
- **A garbled info block.** The check code's high half is not `CACA`.
- **The wrong part entirely.**

All three used to look identical from outside: initialises fine, never reports a
press. The board now names which one it hit.

### What this tells us about the AMOLED

On the board here, all three checks pass. Check code `CACA4E20`, chip type
`0x9220`, firmware `01000006`, resolution 480×480, and the mode unlock confirms.
Waveshare's own `pin_config.h` matches every pin Yoyu uses (SDA 15, SCL 14,
INT 11, RST 40).

So the controller is the right part, it is programmed, it is addressed
correctly, it is in normal reporting mode, and it still reports no press. That
kills the missing-firmware theory this work started from. What remains is the
panel-to-controller connection.

**The AMOLED board is still a display, not a control.** Auto-rotate cycles the
screens and everything else is configured from a browser.

### Upgrading

Over the air from `/update`, or re-flash from the setup page. Wi-Fi, login,
settings and history all survive.
