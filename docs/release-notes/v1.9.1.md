## Yoyu v1.9.1

**Self-hosted boards knew nothing about credits.** Everything v1.9.0 added went
into one of the two places it needed to go.

### Two parsers, one of them fixed

The companion reads Anthropic's response for boards it pushes to. A paired,
**self-hosted board polls Anthropic itself** and parses the response in
firmware. Every credits change in v1.9.0 went into the first one.

So the mode this product is proudest of, the board that runs with no computer
involved, got none of it. It was also worse off than a pushed board, because its
window list named `extra_usage` explicitly and showed **"Extra usage 100%" as a
meter**. That reaches the mascot, which is driven by whichever window has least
room left, so the board said *out of tokens* with the real windows sitting at
53% and 6%.

Found by plugging a second board back in. Both took the same push, both reported
delivered, and then they disagreed completely. One had credits and two windows,
the other had no credits and four, two of which should not have existed. Same
data, two code paths.

### What changed

The firmware now matches the companion:

- **`extra_usage`, `spend`, `limits` and `member_dashboard_available` are
  excluded by name**, not by inspecting a field. `extra_usage` carries a real
  utilization once money has been spent, so no value-based test is safe.
- **The same conservative codename filter.** A known window always shows. An
  unknown one with a reset time shows, since that is what a newly shipped model
  looks like. Only an unknown entry with no reset and nothing used is dropped.
- **Credits are parsed from the same poll**, with the same rule that `enabled`
  means credits can no longer be *spent*, not that none ever were.

Verified on a self-hosted board against a live poll. Credits come back, the
window list is correct, and neither `Extra usage` nor an internal codename
appears.

### Upgrading

Over the air from `/update`, or re-flash from the setup page. Wi-Fi, login,
settings, character and history all survive.
