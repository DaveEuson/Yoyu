## Yoyu v1.16.0

**A screen that tells you in a sentence**, two more themes, and the AMOLED's
keys finally doing something.

### Outlook: the answer, not the arithmetic

Claude's own usage panel leads with a sentence rather than a number to work
out — *"at this pace you'll run out Thursday morning, before the 5:00 PM
reset."* The board has a screen that says the same thing.

Pace already does that calculation and shows its working; **Outlook** says the
conclusion:

```
Weekly · at the rate you are working
tomorrow morning
you run out, before the 5:00 PM reset
```

It picks the window that decides the answer — the one running dry soonest, or
one that has already run out — and it says a **time of day** rather than a
clock time, because "tomorrow morning" is something you can plan around.

The lead-in says what the estimate rests on, and that differs by window: the
session is judged on the last hour, the week on its average since it began. A
projection you cannot see the basis of is a number to distrust. When there is
no pace worth quoting, it says so instead of inventing one — *"spent"*, or
*"too early to say"*.

Outlook is switched on once, the way every screen added since v1.4.0 has been,
and stays off if you turn it off.

### Two more themes: Hazard and Hi-Fi

Both bring a layout of their own, not just a palette.

**Hazard** is an industrial warning plate: diagonal stripe bands top and
bottom, black on safety yellow, one enormous number between them. The stripes
go red when a window is critical. It is the one theme whose state you can read
across a room without reading anything.

**Hi-Fi** is a seventies VU meter, with a needle that pivots below the glass
and a scale whose last three ticks are in the red. The needle reads how much is
**left**, so a full tank swings it right.

That makes fifteen themes over twelve layouts.

### The AMOLED's keys work

That board's touch does not work — a faulty panel, not a driver — so until now
its screens could only change on a timer.

It has three keys along its edge. The left one goes back a screen and **BOOT**
goes forward, so the direction matches the side you press. **Holding** the left
key flips between "% left" and "% used", which is what a long press does on a
board you can touch.

**PWR, in the middle, is deliberately unbound.** It is also the power switch:
hold it for four seconds and the board turns off in hardware. Binding anything
there would teach you to press the one key that switches it off.

A key acts when you let go, and only for a press between 30 milliseconds and a
second, so a resting thumb is not a command and BOOT's five-second factory
reset is never mistaken for "next screen".

### Fixes

- **Unticking the screen set to "show first" now works.** It used to go
  straight back on when you saved, with nothing on the page explaining why. The
  first screen has to be *one of* your screens, not a particular one, so it
  now moves aside to the first screen you kept.
- **The C6's factory reset never worked.** Holding BOOT for five seconds reads
  GPIO0, which is BOOT on the two ESP32-S3 boards but not on the C6, where it
  is GPIO9.
- **Auto-rotate "off" asked the wrong question.** It checked whether a board
  had touch, which kept the AMOLED on a forced timer after it had keys that
  could drive it. It now asks whether the board can be steered by hand at all.
- **The README promised a mode that does not exist.** It offered a
  self-contained setup where the board "refreshes its own token, with nothing
  running on your computer afterward". The board has not been able to do that
  since v1.6.3. Pairing is now described as it works: the board reads your
  usage itself, and your computer tops up its token while it is on.

### For checking

`/api/status` gains `show_used`, and on a board with keys, `keys` (each key's
live level) and `key_presses`.

### Upgrading

Over the air from `/update`, or re-flash from the setup page. Wi-Fi, login,
settings and history all survive.
