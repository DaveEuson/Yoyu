## Yoyu v1.17.0

**A board that says what's wrong instead of sitting blank**, a companion that
remembers its board, and brightness and night-dimming you can set.

### The board tells you why it has no numbers

When the companion couldn't read your usage — Claude Code signed out on your
computer, not installed, or Anthropic rate-limiting the usage endpoint — the
only sign was a red tray icon, and Windows hides tray icons by default. The
board just sat there with no meters. A new owner reads that as "it won't
connect", and so did we, setting up an AMOLED from scratch.

Now the companion sends the board a short notice each cycle, and the Meters
screen shows it in plain words until real numbers arrive:

```
Claude Code signed out on your computer. Run claude, then /login
```

It is word-wrapped to fit all three boards. A board reading usage for itself,
with no notice to show, says its own status the same way. The notice clears as
soon as usage comes through, and lapses on its own after 40 minutes if the
companion stops sending it.

### The companion remembers its board

The downloaded companion forgot its board every time it closed. It kept its
settings — which board to feed, and the key pairing gives it — inside the
temporary folder the app unpacks itself into, which is deleted when the app
exits. Every restart, every login and every fresh download started from
scratch, so a board that was set up correctly went stale overnight.

Settings now live somewhere that outlasts the app:

- Windows: `%APPDATA%\Yoyu`
- macOS: `~/Library/Application Support/Yoyu`
- Linux: `~/.config/yoyu`

Running the companion from source is unchanged.

### Brightness that survives a restart

Brightness could only be changed by swiping, and every reboot put it back to
full, so a board dimmed for a bedroom came back blazing. It is now on the
settings page in five steps from 10% to 100%, a swipe saves too, and the board
starts at your level rather than flashing to full first.

On the 1.47″ C6, 50%, 75% and 100% used to look identical, because the panel is
limited to half power. The setting is now scaled into each panel's safe range,
and on that board the settings page explains why "100%" is dimmer there:
Waveshare warns that running it hotter can leave permanent dark patches.

### Dim overnight at the hours you choose

Overnight dimming was fixed at 10 pm to 7 am. The settings page now has
**Dim from … until …** in half-hour steps, in the board's own 12- or 24-hour
format. The default is still 10 pm to 7 am, so nothing changes if you leave it
alone. A window that ends before it starts runs past midnight; one that ends
when it starts never runs.

### Fixes

- **Start at login silently did nothing on macOS.** The login item was written
  with an unescaped character that macOS refused without saying so.
- **Quitting the companion only stuck on Windows.** On macOS and Linux it came
  back.
- **Linux: the tray app crashed at every login on some desktops.** It was
  started by systemd, which isn't always inside your desktop session. A desktop
  login now uses the desktop's own autostart; a machine with no desktop keeps
  systemd. Existing installs are moved over automatically the next time the
  companion starts.
- **Linux: installing crashed on machines without systemd**, and uninstalling
  left the service running until you logged out.
- **Linux: a menu entry for a companion in a folder with a space in its name
  didn't start.**

The companion is now tested on Windows, macOS and Linux on every change, and
each release launches the apps it built before publishing them.

### For checking

`/api/status` gains `notice` (whatever the board is showing in place of
meters), and `night_from`, `night_to` and `night_now` for the dimming window.

### Upgrading

- **Board:** over the air from `/update`, or re-flash from the setup page.
  Wi-Fi, login, settings and history all survive.
- **Companion:** download the new one from the setup page. It finds your board
  by itself. **If you paired your board, pair it once more after updating** —
  the old app's settings were deleted each time it closed, so there is nothing
  for the new one to carry over. After that, it stays paired.
- An older board ignores the new notice, and an older companion still feeds a
  new board, so the two can be updated in either order.
