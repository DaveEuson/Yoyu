## Yoyu v1.6.5

**Themes.** Six of them, on both boards.

### Pick how it looks

`http://<board-ip>:8080/settings` now has a **Theme** picker:

| | |
|---|---|
| **Night** | the original — dark ground, terracotta meters |
| **Dim** | the same idea at roughly 40% brightness, on a true-black ground |
| **Paper** | light ground, dark ink, for a bright room |
| **Mono** | no colour at all; the meters climb in brightness instead |
| **Nord** | the Arctic palette, using its own green/amber/red for the meters |
| **Tokyo Night** | likewise |

Every theme keeps the three-step meter ladder, so a window that is nearly spent
still looks nearly spent — colour was never the only thing carrying that, which
is exactly why a colourless theme is possible at all.

The mascot does not change with the theme. It is the same character on every
one of them.

### Why Dim exists

On the 2" LCD board, the dark background is *backlit* — the whole panel gives
off a similar amount of light, and the meters read as warm against it. On an
AMOLED, that same background is pixels switched **off**, giving off nothing at
all, so every lit element runs at full brightness against true black with
nothing in between. Identical colours, completely different physics.

Dim is the answer to that, and the AMOLED board starts on it. The LCD board
starts on Night, as before. Either can be changed to any of the six.

Dim has a second benefit on an AMOLED: an always-on display showing the same
labels in the same place is the textbook case for burn-in, and a true-black
ground with dimmer accents gives it much less to burn in with.

### Second board

The **ESP32-S3-Touch-AMOLED-2.16** now gets its own published firmware images,
so it can update itself over the air like the LCD board. Each board's images are
checked at release time to be certain they were built for the board whose name
they carry: both are validly signed, so a board would accept the wrong one, and
the file name is the only thing preventing it.

**Touch still does not work on that board**, and the README now says so plainly
rather than leaving it to be discovered. The controller initialises and reports
its own resolution, then never reports a press. Auto-rotate makes the board
usable in the meantime; everything else is configured from a browser.

### Upgrading

Over the air from `/update`, or re-flash from the setup page. Wi-Fi, login,
settings and history all survive.
